# 自有账号的批量测试入口

双击 `GSA批量测试.command`。按提示输入本机账号文件路径，选择是否开启调试模式，再输入代理 API 地址；API 地址和可选代理连接认证采用隐藏输入，不写入配置或日志。无需把账号密码发到聊天。

复制 `accounts.example.txt` 为 `accounts.txt`，替换成你自己的账号，每行：

```text
邮箱----密码
```

示例中的 `.invalid` 地址会被拒绝，不能直接执行。入口最多接收 20 个不同账号，全部进入同一任务队列，不分批；不允许同一账号重复并发。邮箱去除两端空格，密码保留四个连字符之后的原始字符；密码前后不要添加用于排版的空格。密码内部含有 `----` 也能保留。账号序号是文件内非空行的顺序。

## 固定配置

- 账号认证并发为 2，使用 `spawn` 子进程；每轮尝试有独立进程、HTTP 会话、Cookies 和 SRP 状态。
- 代理库存目标 10，IP 有效期 60 秒；API 链接的 `num=200` 会在实际请求时改为当前所需数量，首次为 10。空闲库存低于 3 条或有人等待时，由唯一供给线程补充，单次最多补到 10 条空闲库存。
- 每个设备或正在执行的操作独占其 IP 租约；绑定在设备上的 IP 不属于空闲库存。库存、设备容量和账号并发分别计数。
- 设备池上限 10；一个设备注册供给线程依次领取 IP、注册设备、将设备加入池。新增设备之间间隔 3 秒。
- 设备达到 2 台就开始认证。账号结束后释放设备使用权，第三个账号可以复用已完成任务的设备，不等待第三台注册完成。
- 批次完成或取消后停止两个供给线程，回收子进程。设备池是容量目标，不要求完成所有 10 台注册后才能结束账号任务。

## 进程与线程

```text
主进程：账号队列、重试队列、设备/IP 租约、结果和日志
  ├─ 代理供给线程 → 监督一次 API 提取子进程 → 代理池
  ├─ 设备供给线程 → 领取 IP → 监督设备注册子进程 → 设备池
  ├─ 认证进程槽 1 → 领取账号、设备及有效 IP → 刷新参数 → GSA
  └─ 认证进程槽 2 → 领取账号、设备及有效 IP → 刷新参数 → GSA
```

两个认证进程槽最多同时执行两轮账号认证；设备注册和 API 提取不计入账号认证并发。主进程统一分配资源，不把账号、设备和代理队列复制给各个工作进程。

路由显式分开：公共客户端配置、Anisette 参数服务及其 WebSocket 使用直连；Apple lookup、midStartProvisioning、midFinishProvisioning 和 GSA init/complete 使用本轮领取的代理。没有有效代理时等待，不将 Apple 请求退回直连。客户端配置按同一服务缓存复用。日志的 provider_route 和 apple_route 标记这两条路由。

首次使用独立的 `config/batch-device-pool/`。单设备测试入口的 5 台直连设备不混入本次代理设备池。后续批次会读取已有注册状态；IP 租约只在当前运行期间复用，跨批次重新领取有效 IP。

## 过期、超时及重试

领取 IP 时，至少保留约 20 秒有效期；注册要求约 25 秒。有效期从 API 提取开始计算，保守地计入提取耗时。开始一轮后固定设备与 IP，不在 init/complete 之间换出口。

每轮 GSA 请求超时默认 15 秒，设备参数请求预算 40 秒。主进程再对整个子进程设置 45 秒硬上限，并在代理租约到期前 2 秒回收；DNS 或底层读取卡住也有进程级退出路径。API 提取子进程硬上限 15 秒。

父进程确认旧子进程结束后才发布超时结果和安排重试，避免两个尝试重叠。超时仅代表未知结果，不能归为密码错误。

设备注册遇到临时连接/读取超时或 HTTP 5xx，最多尝试两次。保留该编号与本地 identifier，释放故障租约后领取有效代理重试；不会把注册失败计成账号密码错误。

默认每个账号最多两轮，包括首次：

| 结果 | 策略 |
| --- | --- |
| init / -20970 | 保留同一设备，退避约 2 秒并加入少量抖动，刷新参数，新进程重试一次；有效 IP 尽量沿用 |
| 临时网络、TLS、HTTP 5xx、进程超时 | 旧进程先回收，放弃故障或过期 IP；同设备领取有效出口后有限重试 |
| 密码错误、账号锁定、需要二次验证 | 不自动重试 |
| complete / -20970 | 不套用 init 阶段的例外重试 |
| HTTP 429（认证、注册或代理 API） | 停止批次分发，剩余项记为未开始，不更换出口继续尝试 |

设备连续累计 5 次尚未恢复的 init/-20970，冷却 600 秒。进入 complete 说明 init 已被接受，清除该设备的初始化拒绝计数。60 秒内 3 台不同设备出现 init/-20970，服务熔断 600 秒并停止当前批次；未开始项保存在结果中。这些阈值是本地运行策略，不能据此断定 Apple 封禁了某台设备。

## 日志

每次运行生成独立的 `logs/batch-时间-进程号/`：

| 文件 | 内容 |
| --- | --- |
| `events.jsonl` | 代理供给、过期、注册、池水位、设备领取与复用、工作进程 PID、阶段耗时、重试和停止事件 |
| `results.jsonl` | 账号序号、最终状态、设备号、尝试次数、错误阶段和错误码、各轮耗时 |
| `summary.json` | 账号总数、并发、设备数、分类计数、批次耗时和停止原因 |
| `debug.jsonl`（调试模式） | 进程启动、HTTP 的 DNS/连接/隧道/TLS/发送/首字节/响应头，设备注册阶段，WebSocket 连接与收发等待，SRP 和 GSA 各阶段的跨度、CPU 时间、状态码和异常类型 |
| `debug-summary.json`（调试模式） | 按角色、阶段和请求类型汇总次数、平均、最大及样本 P95 耗时 |

文件权限 600，目录权限 700。日志不保存邮箱、密码、代理 API 地址、代理连接凭据、设备认证值、Cookies 或响应正文。通过账号序号回查你自己的输入文件。未开始项和被取消的在途项没有密码结论；本版本不会自动继续上一批次的账号队列。

调试记录通过账号序号、设备编号/指纹、代理端点指纹、尝试轮数、子进程 PID、阶段 ID 和请求 ID 关联。代理指纹只用于比较代理端点是否变化，不等于实测公网出口 IP。更换 IP 后仍出现同类错误是需要分析的现象，不能单独证明设备已被封。

调试模式不改变并发或重试阈值，但计时适配器和日志写盘会有开销。HTTP 可记录 DNS/TCP/TLS 等阶段；WebSocket 记录连接总时长及各轮收发等待，尚不单独拆分其内部 DNS/TLS。父子阶段有重叠，不能把所有阶段耗时直接相加。只记录收发字节计数，不记录数据内容；如果进程被硬回收，可能只有对应阶段的开始记录。子进程诊断队列溢出会计入 dropped_debug_events，写盘失败计入汇总。

“密码通过/需要二次验证”依然只是 GSA 密码证明结果，原协议尚不提交验证码或导出业务登录令牌。

## 验证

```sh
.venv/bin/python -m unittest discover -s tests -v

# 可选：真实调度器 + 合成的十个账号/代理/设备，禁止网络
.venv/bin/python tools/offline_batch_demo.py
```

离线检查使用真实 spawn 进程和父进程调度，覆盖并发上限、2 台就绪启动、第三账号复用、同设备/同有效代理重试、新会话与新进程、超时回收、429 停止、代理过期、日志脱敏和 HTTP/WebSocket 代理传递。另外通过本机 HTTPS 服务和独立合成 SRP 服务器验证开启调试后的真实 TLS 校验与密码证明运算。它不证明代理商当前可用，也不代表真实 Apple 认证成功率。
