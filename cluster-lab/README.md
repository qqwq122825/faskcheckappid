# Cluster Lab：独立总控与节点版

这是与现有单机项目分离的离线任务平台。没有导入 `fastcheck`，没有认证 API 适配器，不执行文件中包含的命令或网址。内置任务只有逐行 SHA-256 摘要和带固定延时的合成演示。

## 运行

总控与节点使用同一份 Git 仓库，区别是分别运行 `controller.py` 与 `node.py`。宝塔均选择仓库下的 `cluster-lab/` 作为 Python 项目根目录；仓库外层执行 `git pull --ff-only origin main` 后重启本机角色。完整目录与迁移说明见 [DEPLOY_BT.md](DEPLOY_BT.md)。

需要 Python 3.11+。首次安装：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

分别在两个终端启动：

```bash
.venv/bin/python controller.py
.venv/bin/python node.py
```

- 总控页面：<http://127.0.0.1:18770>
- 节点页面：<http://127.0.0.1:18771>
- 默认仅监听回环地址。本地预览无需管理密码。
- 默认数据分别保存在 `runtime/controller/` 与 `runtime/node/`，不会使用原单机项目的 `data/`。
- 每个节点需要独立数据目录。更多节点可通过 `--port`、`--data-dir` 指定。

第二个本地节点：

```bash
.venv/bin/python node.py --port 18772 --data-dir runtime/node-02
```

三个服务启动后，`tools/benchmark_two_nodes.py` 会复用已连接的节点或创建新的本地节点，上传同一份 10,000 条合成记录文件，以每包 1,000 条分别运行单节点与双节点对照。每个配置为 2 进程 × 2 线程。它逐条验证输出，并将各节点分到的工作包数、准备时间、执行及回传耗时保存至 `runtime/benchmark-two-nodes.json`。这些时间包含本地文件处理和通信，不代表外部服务容量，也没有验证一亿条规模。

在总控点击“添加节点”，复制一次性显示的接入凭证；到节点页面填写总控地址和凭证，保存并连接。然后在总控生成 10,000 条演示，准备完成后点击“开始任务”。

`tools/verify_live.py` 通过真实 HTTP 接口连接一个本地节点，生成 10,000 条 `example.invalid` 合成记录，切成 20 个工作包。节点只进行离线摘要计算，脚本会逐条验证结果摘要、原始行号、唯一性以及两侧确认数量。

```bash
# 两个服务已启动、数据目录为空的验收环境中运行
.venv/bin/python tools/verify_live.py
```

验收结果写入 `runtime/verification.json`。该脚本不进行外部账号认证。演示中的每条记录延迟是人为设置，演示速率不能作为业务吞吐量依据。

## 总控页面

0.3 版使用 Vue 3、TypeScript、Vue Router 和 Element Plus 组件。左侧固定菜单，正文 16px，大号任务统计。前端源码在 `frontend/`，编译产物在 `clusterlab/static/ui/`；Python 同源提供页面和 API，不依赖外部 CDN。

- **首页**：节点总数、在线数、工作节点数、排队任务数，当前任务摘要与等待队列。详细结果集中在任务详情，首页没有任务创建入口。
- **任务管理**：上传 TXT 后自动加入持久化队列，支持搜索名称、筛选状态、查看排队位置。创建弹窗可设置单条超时和 0–5 次重试；每包最多 10,000 条由总控自动管理。
- **任务详情**：单张“进度与结果”大屏展示本次统计，执行明细默认收起；继续/暂停、移出队列与 TXT 导出都在同页。
- **节点配置**：实时状态、整机 CPU/内存/上下行、进程线程配置、暂停接单和停止工作。
- **运行日志**：最近通信和任务事件。
- **系统设置**：单个分片最大条数（50–10,000 条，默认 10,000），角色、版本和功能范围。修改分片上限仅对新任务生效，已有任务保持创建时的分片配置。

任务按加入队列的顺序执行。同一时刻只派发当前任务的分片；全部结果确认后自动开始下一任务。文件准备较慢的队首不会被后面的任务超越。暂停当前任务会保留位置，在途继续完成；未执行完的当前任务会阻止后续任务开始。排队任务可以移出后重新加入。准备失败的任务自动跳过；异常待确认分片仍须核对，不会自动重跑。队列与暂停状态会在总控重启后保留。

当前大屏使用离线任务的真实处理统计，未采集的失败、超时类别显示为 `—`。

已完成任务导出 TXT 原始记录，每行一条，保留原始顺序、重复记录和换行。下载文件名使用北京时间导出日期和结果类型，如 `2026-11-13_处理成功_10000条.txt`。内部 JSONL 仅用于分片校验，不作为下载格式。当前离线执行器全部记录归为处理成功，不做账号结果分类。

任务速度按浏览器观测的本次执行增量估算，首次打开没有完整采样窗口；首页速度为节点合计。两者不是性能承诺。记录状态从实际工作包行数汇总，最后一个不足整包的工作包也按真实数量计入。

每个节点有两种不同操作：

- **暂停接单**：停止领取新工作包，在途工作继续执行并回传。
- **停止当前工作**：发出持久化停止版本号，暂停接单，节点在心跳中收到后中止所属执行进程。总控显示“停止中”，收到节点确认后才清除在途状态。已确认结果保留，未完成工作包进入待确认，不自动重跑。停止确认前不能恢复接单。

CPU 和内存为整机占用；上下行为活动网卡合计（排除回环网卡）的字节增量，并非某个任务专用流量。本地两个节点共用一台电脑，因此宿主机测量接近。未采集或离线时显示缺失值，不伪装成零。

节点卡片通过“设备列表”打开独立设备池抽屉。预计设备池数量只保存到当前浏览器，可作为界面预览；不会提交 API 或下发节点。设备列表为空、实际和就绪数量显示缺失，初始化按钮禁用并标注设备服务未接入。节点设置弹窗只保留执行参数与未启用的传输限速位置。离线执行器不会申请设备，也没有修改服务器网络限速。配置进程、线程对下一次领取生效。

总控不运行执行器。它负责接收并准备输入文件、保存任务状态、派发工作包和验证结果。文件上传到总控，因此总控会经手输入；不能宣称总控完全不接触输入数据。

## 节点页面

节点默认页面简化为 Element Plus 连接表单和状态提示。部署时连接一次，日常调度、并发设置与停止均在总控进行。本机工作包记录通过“本机工作包”入口查看。

- 自己的总控连接配置、最近心跳和连接错误。
- 本机执行进程数、总控配置、本机硬上限。
- 工作包执行进度、待回传和总控已确认数量。
- 本机持久化记录。接入凭证保存后不再回显。

本机上限由 `node.py --max-processes 10 --max-threads 100` 设置。总控期望配置超过本机上限时取较小值。一个节点同时领取一个最多 10,000 条的工作包，节点协调器再在本机拆给全部工作进程，每进程使用配置的线程池。配置修改对新领取的工作包生效，在途工作包保留原配置。

## 状态与可靠性

1. 上传不把完整文件读入内存；源文件流式写盘。
2. 后台逐行解析，单行最多 64 KiB；每包最多 10,000 条并同时受 32 MiB 字节预算约束。原文件只保存一份，每包在 SQLite 记录起止字节与 SHA-256，不再生成重复的 `.part` 文件。
3. SQLite 只保存在总控本机。工作节点通过 API 访问，不共享数据库文件。
4. 工作包领取、配置和结果提交分别校验节点身份和当前租约。
5. 心跳续租；过期进入 `unknown`（待确认），不自动重跑执行中任务。
6. 节点先落盘，再上传；总控验证条数、行号和文件 SHA-256 后确认。
7. 重复提交只确认一次；确认响应丢失时，下一次心跳可补齐确认状态。
8. 节点重启不会静默重新执行中断工作；待回传结果从本机数据库恢复。
9. 总控重启保留任务、租约和结果。准备中的文件会从头重新准备，尚未进入执行队列。
10. 已确认结果保留在节点和总控本地，不自动清理；当前版本需按磁盘容量安排保留策略。

任务历史展示最近 50 个任务，节点本机记录展示最近 60 个工作包；总览累计数量从完整数据库统计。节点每秒把当前包的已处理数上报给总控，页面也每秒轮询；进度条显示实时已处理，完成状态仍以总控确认全部结果为准。

### 1 亿条边界审计

0.3.6 恢复了任务创建页的重试次数；节点新建默认为 10 进程 × 100 线程，设置页可一键填入本机上限。旧版前端强制卡在 32 线程的节点，当本机上报支持 100 线程时会升级为 100，下一个工作包生效。

认证执行器把密正、密码错误、双重验证、锁定、超时和未判断的累计值写入本地进度，节点每秒上报给总控。页面运行中即显示实时分类；工作包最终确认时在同一事务中用最终计数替换实时计数，不会重复累加。运行中用时和速度也改为根据服务器时间与实时已处理数计算。

0.3.5 改为两级调度：总控每 10,000 条建立一个字节索引包，一个节点同时只领一包，节点内部协调器使用全部配置进程和每进程线程池。子进程结果按原始行号合并，一秒心跳在发送前直接刷新聚合进度，避免主循环与心跳竞态造成两秒无反馈。任务超时与重试值也改为从任务正确下发，不再默认回落到 20 秒 / 0 次。

4 节点长时验证工具：

```bash
.venv/bin/python tools/verify_four_nodes_soak.py \
  --input /path/to/large.txt \
  --report runtime/four-nodes-soak/report.json \
  --duration 600 --processes 10 --threads 10
```

工具通过真实 HTTP 启动一个总控和四个节点，核对字节索引总长度、单份源文件、每秒进度、40 个工作进程、分包分布、节点回传队列以及最终下载 SHA-256。`simulate` 模式只在本机计算摘要，不访问外部认证服务。

2026-11-14 增加了 100,000,000 行的元数据级回归：按 10,000 条一片创建 10,000 个分片，直接读取第 99,999,951–100,000,000 条时只打开最后一个结果文件。分类分页把每片分类计数与确认事务一起持久化，可跳过整片，不再从第 1 条重扫。

账号执行器现在每个工作包只保留 `2 × 线程数` 个 Future，结果写入时增量计算 SHA-256，设备用量从“每账号读改写一次 JSON”改为“每工作包加锁合并一次”。页面上传改用原始字节流，避免 multipart 临时副本和总控再拷贝造成的双份磁盘峰值。

2026-11-14 又使用 403,451 字节的本地 TXT 跑了一次真实 HTTP 验收：总控 + 4 个节点，每节点 10 进程 × 每进程 20 线程，10,002 个输入行按 250 行切成 41 包。四节点分得 11 / 10 / 10 / 10 包，最大同时在途 40 包；10,002 行全部确认，行号唯一，摘要逐行匹配，回传队列为 0，下载 TXT 与输入逐字节相同。首轮验收暴露了 Waitress 不能把中文下载文件名直接编码为 HTTP 头的 500 错误，修复为 RFC 5987 百分号编码后重跑通过。该验收使用本地 `simulate` 摘要执行器，没有将账号内容发送到外部认证服务。

没有完成十台真实服务器或一亿条真实文件的端到端容量验证。当前 HTTP 上传上限 8 GiB，不支持分段续传；一亿条记录实际需要的磁盘容量、准备时间和外部服务限流必须在目标机群实测。多任务按创建顺序派发，尚未加入优先级或配额调度。总控高可用、自动升级和自动数据清理未实现。

## 前端开发和打包

开发机需要 Node.js 20.19+ 或 22.12+。服务器使用已经生成的 ZIP 时仅需 Python，不需要 Node.js。

```bash
# 开发：先启动 Python 总控，再启动 Vue 开发服务
cd frontend
npm ci
npm run dev
```

Vite 打印本地开发地址，`/api` 代理到 `127.0.0.1:18770`。默认代理总控；检查节点可访问 Python 提供的已构建页面。

```bash
# 在 cluster-lab 目录一键构建并生成两个角色的部署包
.venv/bin/python tools/build_release.py
```

该命令依次执行锁文件安装、TypeScript 检查、Vue 构建、Python 角色打包。生成 `release/cluster-lab-controller-0.3.6.zip` 和 `release/cluster-lab-node-0.3.6.zip`。包内已有前端静态文件；运行数据、输入、结果、节点凭证、浏览器会话密钥以及 `node_modules` 均不进入安装包。部署说明见 `DEPLOY_BT.md`。

若前端已经构建且没有变更，仅更新 Python 后可运行 `.venv/bin/python tools/package.py`。直接使用源码首次启动前，需 `cd frontend && npm ci && npm run build`；使用发行 ZIP 无需此步骤。
