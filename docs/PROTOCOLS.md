# 网页 / GSA 协议及结果分类说明

更新日期：2026-11-13。实测报告保存在本机 data/ 下，不随发布包分发。本文依据当前项目代码和本机实测，不是 Apple 内部错误码的官方定义。运行和配置见 [TASKS.md](TASKS.md)；分类参考数据见 [classification_reference.json](../fastcheck/protocols/classification_reference.json)。

## 1. 先分清两个错误码

**`-20970` 与 `-20209` 不应合并成同一个含义。**

| 实际响应 | 当前项目分类 | 能报告的结论 | 不能直接推断 |
| --- | --- | --- | --- |
| GSA init / -20970 | `init_refused` | 本次初始化被拒绝，具体原因未确定 | 必然冻结、密码错误、设备封禁 |
| -20209，且不是 HTTP 5xx/429 等服务或限流响应 | `security_lock` | 本次响应被项目识别为账号安全锁定 | 与所有其他拒绝码同义、永久封禁、密码一定正确 |

用户确认的“已冻结账号”样本里，两种返回都出现过。这证明同一个已知样本群可能出现不同响应，不能证明两个码语义相同。它们可以共同位于“认证未完成”这个大类，子类仍须分开。

后续分类应分别保存：用户提供的已知状态、服务端原始响应字段、项目从响应推导的分类。例如“用户已知冻结 + 本次 init/-20970”可以同时成立，但从这次响应本身只能得出初始化拒绝。

## 2. 两条协议的流程

“协议一”是网页 `web`，适配器为 `idmsa.py`；“协议二”是 GSA `gsa`，适配器为 `gsa_status.py`。两条通道都使用 HTTPS，与代理地址使用 HTTP 还是 HTTPS 是不同问题。`anisette-version=1/3` 也不是网页/GSA 的编号。

### 网页：协议一

```text
创建本轮独立 HTTP/Cookie 会话与 SRP 临时密钥
  → POST https://idmsa.apple.com/appleauth/auth/signin/init
  → 收到 salt、b、c、iteration、protocol 和会话信息
  → 本地计算密码证明
  → POST .../signin/complete?isRememberMeEnabled=true
  → 按 HTTP、serviceErrors、authType 分类
  → 关闭本轮会话
```

init 提交 `accountName`（账号）、`a`（SRP 公钥，Base64）、`protocols`（支持的协议）。此时尚未提交密码证明。complete 提交同一账号、本轮 `m1`、`m2`、`c` 等信息。代码不降级为提交明文密码。

Cookie、`scnt`、`X-Apple-ID-Session-Id`、SRP 私钥及挑战上下文只能在本轮 init/complete 内沿用，不能跨账号混用。每轮认证新建客户端，即使同一个线程复用，也不复用上个账号的登录状态。

当前 `X-Apple-Widget-Key` 和 `X-Apple-OAuth-Client-Id` 来自原项目硬编码常量，注释标为 iCloud 网页客户端公开标识；尚未核实该值与当前官方网页配置是否一致。它们标识客户端应用，不是本地设备池编号；不应为了制造“新设备”随机改写。当前 User-Agent 固定。一轮新的本地会话不保证服务端将其认作互不关联的新设备；账号字段仍指向同一个账号。

### GSA：协议二

```text
读取持久设备身份；必要时注册 → 刷新本轮 Anisette 参数
  → POST https://gsa.apple.com/grandslam/GsService2，o=init
  → 收到 Status.ec 和 SRP 挑战；拒绝则停止
  → 本地计算 M1
  → 同一地址提交 o=complete
  → 验证服务器 M2，再分类密码证明及二次验证状态
  → 关闭本轮会话
```

请求编码为 XML plist，`Header.Version=1.0.1`。init 的主要字段：

| 字段 | 内容 |
| --- | --- |
| `u` | Apple 账号邮箱，服务端在初始化阶段就能取得 |
| `cpd` | 设备认证参数，如 X-Apple-I-MD、X-Apple-I-MD-M、X-Apple-I-MD-LU、routing info、设备标识及区域设置 |
| `A2k` | 本轮 SRP 公钥字节，不是密码证明 |
| `ps` | `s2k`、`s2k_fo` 等受支持的协议列表 |
| `o` | `init` |

因此，init 可以返回账号相关拒绝，不必等到密码校验。`-20970` 是从 Apple 响应的 `Response.Status.ec` 读取的业务码，不是程序自己制造的设备故障结论。complete 使用本轮 `u`、`cpd`、`M1`、`c` 和 `o=complete`；不能将另一轮的挑战或设备临时参数拼接进来。

`/v3/client_info` 返回配套客户端描述与 User-Agent，不是某台独有设备的身份。持久设备状态主要是本地 identifier 和注册后的 adi_pb；每次认证仍刷新临时参数。设备服务接收设备相关数据，Apple 账号密码不发送给它。

GSA 对成功返回执行 M2 校验后才设置 `password_verified=true`。网页适配器按其 HTTP/authType 响应分类。两者目前都不继续提交二次验证码或导出业务登录会话；`need_2fa` 不能写成“已经完整登录成功”。

## 3. 分类必须同时看协议、阶段、HTTP 与业务码

HTTP 状态与 Apple 业务码属于不同层。HTTP 200 不代表账号正常；HTTP 401 也不是业务码 -20283。建议未来记录以下独立字段：

| 字段 | 用途 |
| --- | --- |
| `protocol`、`stage` | web/gsa；prepare、init、complete、worker 等 |
| `http` | 实际 HTTP 响应码；没有收到响应时为 0 或未知 |
| `apple_ec` | 响应中的业务码；缺失时为空，不用 HTTP 状态代替 |
| `status`、`kind` | 项目分类及网络/协议/服务等原因类别 |
| `password_verified` | 仅在实现得到相应证据时设置，不从 init/200 推断 |
| 用户已知状态及来源 | 可记录 user_report/frozen，独立于从响应推导的状态 |

当前网页和 GSA 结果均直接记录实际 HTTP，调试事件另记 `http_init`/`http_complete`。旧版部分 GSA 结果没有顶层 HTTP 字段，可通过安全计时事件按编号和阶段关联补齐；没有字段不能自行填成 200。

| 观测条件 | 建议业务子类 | 处理与边界 |
| --- | --- | --- |
| GSA init / HTTP200 / -20970 | 初始化拒绝 `init_refused` | 不判密码、不直接判冻结或设备封禁；新入口不自动重试 |
| 响应 -20209 | 安全锁定 `security_lock` | 保留原码和阶段；停止该账号，不猜密码结果 |
| 网页 complete / HTTP401 / -20283 | 账号信息被拒绝 `credentials_rejected` | 不直接合并为冻结或密码错误 |
| GSA complete / -22406 | 项目密码拒绝分类 `wrong_password` | 必须保留 complete 上下文；不能套用到 init 或其他协议 |
| 网页 init / HTTP400 / -900007 | 初始化未完成 `init_incomplete` | 尚未提交密码证明，无密码结论 |
| HTTP503、其他 5xx | 服务/链路错误 `server` | 不作为账号冻结或密码错误的证据 |
| HTTP429 | 限流 `ratelimit` | 停止批次，不换出口继续提交 |
| 未收到 HTTP 响应 | 网络/代理/TLS/超时 | 不当作密码错误；缺失结果保持未知 |
| init / ec=0 且挑战完整 | 初始化接受 | 只允许继续本轮认证，不证明密码有效或完整登录成功 |

分类先识别 HTTP 5xx/429 和传输失败，再解释合适上下文中的业务码；不能仅凭一个数字做全局匹配。未列出的响应保留为未判断，保留原始的安全元数据供分析。

## 4. 总控界面计数

新总控每秒更新状态面板；窗口较窄时自动换行并覆盖原面板，不刷过程事件。非终端输出每秒追加一行。最终强制输出一次结束快照。

| 显示列 | 计入条件 |
| --- | --- |
| 已运行 | 已得到最终记录、且至少派发过一次的不同账号数；不重复累计重试 |
| 剩余 | 总数减已运行，包含正在运行、等待资源、等待允许的重试及未开始账号 |
| 密正 | `valid`，以及密码已验证的 `needs_setup` |
| 错误 | 仅明确的 `wrong_password` |
| 双重 | `need_2fa`，单独计数，不重复计入密正 |
| 锁定 | `security_lock`、`locked` |
| 超时 | 明确超时的网络失败，或在自身硬期限内未结束的任务 |
| 未判断 | init_refused、credentials_rejected、5xx、其他网络/协议错误、未激活、设置结果不明及被连带中断的在途任务等 |

各结果列互斥，相加等于已运行。未开始任务不计入这些结果列；批次中止时，剩余可以大于 0。速度是已运行账号数除以本批次用时的每小时换算，包含准备时间，不是成功登录速度。

一个线程超时可能需要回收整个工作进程；被连带中断但尚未到自身期限的任务计入未判断，不全部误记为超时。面板分类逻辑在 `../task_status.py`，任务协调在 `../auth_supervisor.py`。

## 5. 本机证据及适用范围

### 82 个用户确认冻结的账号，零重试、两边实际并发 10

| 项目 | 网页 | GSA |
| --- | --- | --- |
| 准备完成后的处理区间 | 32.523 秒 | 35.097 秒 |
| 单账号中位耗时 / P95 | 3.312 / 8.121 秒 | 3.675 / 5.340 秒 |
| HTTP503 账号数 | 33 | 1 |
| 主要业务码 | -20283：32；-20209：4；-900007：8 | -20970：74；-20209：6 |

GSA 其余为 1 个 HTTP503、1 个网络失败；网页还有 1 个 HTTP502、4 个无 HTTP 响应。GSA 全部在 init 结束。GSA 初始化前准备约 64.699 秒，其中补齐 7 台设备；这段不应混作账号认证耗时。

74 个 GSA/-20970 中，网页对应 31 个 HTTP503、30 个 HTTP401/-20283、8 个 HTTP400/-900007、1 个 HTTP502、4 个无响应。因此 -20970 与网页 503 不一一对应。

两轮顺序执行，代理租约及时间窗口不同；这是已知冻结样本的反馈对照，不能推出正常登录性能或错误码的普遍含义。本机报告：[测速结果](../data/cli-logs/benchmark-20261113-000431-8533/测速结果.txt)。

### 正常账号的初始化字段变体

同一个正常账号、本地设备 5、相同直连出口；每轮刷新正常临时数据并新建 SRP 密钥，仅故意损坏一个字段，均只请求一次 init：

| 变体 | 实际业务码（均为 HTTP200） |
| --- | --- |
| 正常前置基线 | 0，收到挑战 |
| u 留空 | -80002 |
| 篡改 cpd 内的 X-Apple-I-MD | -22409 |
| A2k 置零 | -22402 |
| ps 使用不支持的协议 | -22401 |
| 恢复正常参数 | 0，收到挑战 |

四个变体都没有触发 -20970，不能把它笼统等同于“设备参数坏了”；但这不是其他错误组合永远不会返回 -20970 的证明。表中变体与错误码是一轮观测，不是官方或通用参数错误字典。本机报告：[参数对照结果](../data/cli-logs/init-fields-20261113-001422-9264/对照结果.txt)。

## 6. 入口、重试及日志

当前总控入口为项目根目录 `cli.py`（或 `scripts/macos/` 下对应入口），共用 `fastcheck/cli.py`。运行时可输入账号文件、进程数、每进程线程数和首批 IP 数量；`data/config/task-settings.json` 提供 CLI 回车沿用的默认值。默认首批 IP 目标为本批账号数，单次 API 最多 200 条，后续按未分配任务数收缩库存目标，仍淘汰过期租约。主进程动态分配任务、IP 和设备，不静态平均切成固定账号分组。当前配置 GSA 单设备并发为 0，随全局线程容量，因此 2 台设备可共享所有工作线程；设置为 1 可恢复独占。每轮仍有独立会话/SRP 和参数刷新。

设备调度由`fastcheck/device_scheduler.py` 根据在途数量及选择策略分配，默认优先让新增设备参与，也可按使用量和上次派发时间均衡，支持交错休息。默认每 20 轮可安排 30 秒休息、最多同时 1 台，保留通常为 2 台的健康就绪下限；这些均是可调的本地参数，不能解释为 Apple 的限额或解除限制规则。调度器不接收错误码，因此 -20970 不触发设备故障、身份更换或账号重试；已有设备身份在休息前后不变。

当前默认 `max_attempts=1` 表示首次尝试一次、零重试；`max_attempts=2` 只允许符合策略的初始化前/初始化阶段临时网络失败再试一次。`retries=0` 固定传给底层适配器。账号拒绝、锁定、-20970、complete 结果未知及在途进程回收不自动重投。测速入口固定为每账号每通道一次。

归档的旧版 `GSA批量测试.command` / `archive/legacy/gsa_batch.py` 仍保留历史设备拒绝计数与重试策略，不应用于解释 -20970 的业务含义。新总控不会因这个码累计设备封禁。

调试提示输入 y，结束后在 `data/cli-logs/tasks-*` 查看 `events.jsonl`、`results.jsonl`、`summary.json`、`debug.jsonl` 和 `debug-summary.json`。不开调试仍保存基本事件、结果和汇总，调试模式另记网络/协议阶段耗时。结果日志不保存账号密码、Cookie、认证材料、响应正文或 API 地址。按用户要求，`exports/` 另存含原始账号密码的私有分类文件；未判断的安全诊断单独存储。Web 下载需要登录，过程日志 ZIP 不包含分类账号文件。

代理 API 按用户要求单独保存到本机 `config/proxy-api.json`，权限 600，所在目录被 Git 忽略。三个新入口共用，提示处回车沿用，输入新地址覆盖。API 中的密钥会随链接保存在这个本机私有文件，区别于不含凭据的公开调度配置；代理连接认证仍仅本次使用。

HTTP503 的标准含义参见 [RFC 9110 §15.6.4](https://www.rfc-editor.org/rfc/rfc9110.html#name-503-service-unavailable)；本项目日志不足以确定每次 503 的具体内部原因。
